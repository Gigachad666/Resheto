# Масштаб и измерения

Измерено 25.10.2026, Release MSVC 19.44.35228, Qt 6.8.3, Windows 11 x64 (10.0.26200), AMD Ryzen 7 8845HS, физическая память 16 438 382 592 байта. Файлы на локальном D:. Модель накопителя не определялась. Последний прогон выполнен после сборок/тестов, без их параллельного запуска. Исходные JSON-измерения сохранены в `docs/measurements`, данные/SQLite — `build/final-20261025/measure`.

## Профиль и бюджет

**До замера** задано 120 секунд на отдельный процесс подготовки и на каждый из четырёх процессов проверки. Это ограниченный инженерный прогон, позволяющий завершить три размера блока и обход/хранение тысячи файлов за несколько десятков секунд. Скрипт прерывает процесс при превышении и возвращает ошибку; превышений итогового прогона не было. Исторические build/audit-* к этому измерению отношения не имеют.

`resheto-benchmark prepare` создаёт детерминированные **100 000 HASH + 1 000 PATTERN**, отдельно малый набор **1 HASH + 5 PATTERN**, файлы 64/256 МиБ и 1 000 малых файлов. Все записи помечены «СИНТЕТИКА», базы — synthetic. Это не реальные угрозы и не показатель покрытия.

Большие файлы заполнены q, точное совпадение начинается на 65 534 (переход блока), другое стоит у конца. В наборе есть маска, fixed offset=17, шаблон 60 000 байт и 995 длинных почти совпадающих шаблонов 9 022..13 000 байт с отличающимися хвостами. В 1 000 файлах повторены восемь независимых случаев: HASH, переход блока, конец, маска, fixed offset; отрицательные смещённый fixed, длинный почти совпавший шаблон и обычные данные. Ожидается 625 совпадений. Размеры большинства малых файлов 8 КиБ, отдельные — 60 000 байт и короткая HASH-фикстура.

Ожидаемые id/смещения задаются генератором сценария явно, не вычисляются поисковым индексом. Каждый большой файл сканируется блоками 4 КиБ, 64 КиБ и 1 МиБ; ответ одинаковый (PATTERN-0000, offset=65534). Каждая из 1 000 строк проверяется по ожидаемому виду/id/смещению; затем тот же каталог проходит runJob с настоящим хранением и повторным открытием (1000 checked, 625 matches, 0 errors). Обычный CTest не запускает этот большой сценарий и ничего не скачивает. В CTest есть независимый побайтовый oracle на 1000 правилах и четыре размера окна, плюс прежние регрессии длинных шаблонов/масок/размера/отмены.

## Структуры и ограничения

HASH — QHash digest → упорядоченные кандидаты с проверкой min/max. PATTERN — общий Ахо–Корасик по значимым якорям до 16 байт, затем проверка полного кандидата; fixed offset отдельно. У automaton suffix/output links без размножения списков. При 2048 PATTERN максимум 32769 плотных узлов переходов, около 34 MiB плюс контейнеры; при текущих повторяющихся якорях узлов меньше. Все структуры живут в неизменяемом снимке.

Повышены и сохранены явные верхние границы: 200000 записей, 2048 PATTERN, 65536 байт на шаблон, 128 МиБ value+mask, 256 МиБ SQLite/JSON. Полный файл не читается для каждого правила. Хвост maxPattern−1 означает повторную обработку перекрытия: блок 4 КиБ при шаблоне 60 000 байт заметно дороже 64 КиБ/1 МиБ, что видно в замерах. Патологические маски с часто встречающимся одним значимым байтом могут дать много кандидатов; отмена проверяется и внутри поиска. Универсальной гарантии пропускной способности для произвольных баз нет.

Рабочая поставка 11632 HASH измерениями синтетики не дополняется. Пиковая память максимальных разрешённых 200000/2048 со всеми предельными длинами отдельно не измерена. Linux ru_maxrss-ветвь предусмотрена, на Linux не запускалась.

## Повтор

PowerShell 7, Qt bin в PATH, из корня; каталог Output должен отсутствовать:

```powershell
./scripts/measure.ps1 -Bin build/final-20261025/Release -Output build/performance-new
```

Вручную (нужно самостоятельно ограничить процессы по времени):

```powershell
./build/final-20261025/Release/resheto-benchmark.exe prepare build/performance-data
./build/final-20261025/Release/resheto-benchmark.exe run build/performance-data large 64
./build/final-20261025/Release/resheto-benchmark.exe run build/performance-data large 256
./build/final-20261025/Release/resheto-benchmark.exe run build/performance-data small 64
./build/final-20261025/Release/resheto-benchmark.exe run build/performance-data small 256
```

Скрипт сохраняет environment.json, prepare.json, четыре отчёта и stderr каждого процесса. Код 2 означает неверное ожидание или ошибку, не успешный замер. При новой сборке/изменении правил используйте новый каталог. Версия результата/имена данных не влияют на алгоритм сканера.
