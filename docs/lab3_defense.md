# Как устроено Решето на этапе 3

Материал для объяснения реализации и показа на защите. Рабочий каталог: `D:\DeleteMeIDareU\Resheto`. Описано фактическое состояние на 20.10.2026: ручная сигнатурная проверка, GUI, CLI и локальное хранение. Служба, IPC, эвристика, наблюдение, процессы, сеть и карантин относятся к следующим этапам.

## Сортировка и фильтрация

В TASK_LAB3.md явно требуются таблица результатов, сводка и просмотр сохранённых результатов. Отдельного требования сортировки столбцов или фильтра «Только совпадения» там нет. `min_size/max_size` — ограничения применимости сигнатуры к файлу, а не фильтры интерфейса. В доступной пояснительной записке GostLab2_FINAL.docx явного требования сортировки/фильтрации тоже не найдено. Полный файл ТЗ UsualGostV2.docx, упомянутый в PROJECT_CONTEXT.md, отсутствует; утверждать, что такого требования нет в нём, нельзя.

В текущем GUI нет ни сортировки по заголовкам, ни фильтра по результату/пути. Хранилище отдаёт строки в порядке записи, по 200 на страницу. Ограничение размера страницы удерживает память интерфейса, но поиск обнаружений неудобен. Уместная доработка в рамках этапа 3: выбор «Все / Совпадения / Не проверены», поиск по пути и сортировка. Фильтр и сортировка должны применяться ко всему заданию до выделения страницы; сортировка только текущих 200 строк не решит проблему поиска файла на последующих страницах. Эти функции пока не реализованы.

## Почему в путях есть demo

`demo-run` — выбранное имя каталога для безопасного воспроизводимого набора. Оно не включает особый режим анализатора. Можно выбрать другое имя и любой файл/каталог для сканирования. GUI, CLI и тесты используют одно ядро: оно читает реальные байты и не подставляет ответы по именам файлов.

Различаются механизм и содержание базы: механизм работает, но поставляемая база содержит пять активных тестовых сигнатур и одну отключённую. Это база собственных безопасных примеров, а не промышленная база реальных угроз. Программа обнаружит реальную угрозу только при наличии подходящей сигнатуры и выполнении её условий; всестороннее распознавание вредоносного ПО не заявляется.

Короткая тестовая маска `AB ?? CD 12` может встречаться в посторонних двоичных данных. Совпадение с ней в файле ONNX показывает работу поиска, но не устанавливает вредоносность модели. Вывод «Совпадений не обнаружено» также не доказывает безопасность файла.

## Какие файлы за что отвечают

Пути в таблице отсчитываются от корня проекта.

| Файл или каталог | Назначение |
| --- | --- |
| data/demo_signatures.json | Читаемые исходные описания тестовых сигнатур: id, имя, вид, значение, маска, смещение, размеры, версия, enabled. Не используется напрямую при сканировании. |
| demo-run/signatures.db | Выбранная рабочая SQLite-база сигнатур. При анализе открывается только для чтения. Путь задаётся в GUI или --db. |
| demo-run/signatures.db.sha256 | Контрольная сумма всего файла базы. Помогает обнаружить изменение/повреждение; не является цифровой подписью издателя. |
| demo-run/resheto.db | Задания, результаты файлов, обнаружения и события. Это история, а не база правил обнаружения. Путь — поле «Результаты SQLite» / --storage. |
| demo-run/fixtures/ | Безопасные файлы с заранее известным содержимым, включая отрицательные примеры. Их можно проверять обычным сканером. |
| demo-run/expected.json | Эталонные итоги для проверки набора. Сканер этот файл не читает для принятия решения. |
| demo-run/*.jsonl | Сохранённый консольный вывод отдельных проверок; пригоден для сравнения и отчёта. |
| build/audit-fixes/Release/ | Актуальные Windows-программы после исправлений аудита. Здесь находятся GUI, CLI, генератор и исполняемые тесты. |
| .tools/ | Локально установленные SDK Qt и инструменты подготовки/сборки. Это не сканируемые данные и не база угроз. |

`signatures.db` не загружается из сети и не появляется из неизвестного источника: утилита `resheto-prepare.exe` создаёт её из выбранного JSON и формирует соседний manifest. Эта же утилита может создать только базу: `--database-only`. Чтобы изменить правила, готовят новый JSON/новую базу; готового редактора сигнатур и автоматического обновления в GUI нет. Каждое новое задание повторно проверяет базу. Текущее задание удерживает неизменяемый снимок правил в памяти.

Каталог `demo-run` не является обязательным местом хранения: у него такое имя, потому что при запуске явно переданы относительные --db и --storage. Без --storage используется пользовательский каталог приложения Qt; фактический путь виден в GUI. Проверяемые файлы и две рабочие базы имеют разные роли. Собственные активные базы, manifest и SQLite sidecars исключаются из области анализа.

## Как проходит сканирование

1. Пользователь выбирает файл/каталог, рекурсивность, базу сигнатур и хранилище, нажимает «Начать».
2. GUI формирует Request и передаёт его Controller. Один рабочий поток выполняет задание, а UI продолжает обрабатывать события. Предусмотрен один ожидающий запрос.
3. Ядро сохраняет начало задания, проверяет контрольную сумму, схему и записи signatures.db, загружает снимок активных сигнатур. Ошибка базы даёт ошибку готовности, а не отсутствие совпадений.
4. Каталог обходится постепенно. Ссылки/reparse points и специальные файлы пропускаются. Корень имеет глубину 0, разрешены каталоги 0..256. Ошибка отдельного объекта не останавливает остальные ветви.
5. Обычный файл открывается для чтения. Фиксируются его идентичность, размер и метаданные. Содержимое читается блоками по 64 КиБ по умолчанию.
6. На тех же блоках вычисляется SHA-256 и ищутся применимые PATTERN. Хвост до максимальной длины шаблона минус один соединяется со следующим блоком — совпадение между блоками не теряется.
7. После чтения проверяются открытый объект и привязка пути. Ошибка, отмена, изменение/подмена приводят к «Не проверен». Проверка метаданных не создаёт атомарный снимок файловой системы.
8. Результат, обнаружение при совпадении, событие и счётчики сохраняются короткой SQLite-транзакцией. Ошибка записи видима. Содержимое файлов в журнал не помещается.
9. GUI опрашивает прогресс; подтверждённые результаты читает из SQLite страницами. Общий точный объём заранее не вычисляется, поэтому индикатор не обещает точный процент.

«Остановить» устанавливает атомарный флаг отмены. Он проверяется при обходе, между блоками и во время длительного поиска. Завершённые результаты сохраняются; ещё не посещённые файлы не перечисляются. Закрытие GUI отменяет его задание и завершает рабочий поток: независимой службы на этапе 3 нет.

## Два вида сигнатур

**HASH:** SHA-256 всего содержимого сравнивается с 32-байтовым digest из базы. Переименование файла не меняет его содержимое и хеш. В примере hash.bin совпадает; hash-changed.bin отличается одним байтом и не совпадает с этой HASH-сигнатурой. SHA-256 — хеширование, не шифрование.

**PATTERN:** ищется последовательность байтов. Нулевые байты разрешены. Маска `1011` означает сравнение первого, третьего и четвёртого байтов; второй игнорируется. Необязательный offset фиксирует позицию от начала файла, начиная с нуля. min_size/max_size ограничивают размер всего файла.

На один файл сохраняется одно выбранное основание: PATTERN с минимальным смещением, при равенстве — минимальный id; если PATTERN нет, первый HASH по порядку id. Чтение продолжается до конца даже после найденного PATTERN, чтобы поздняя ошибка не стала успешным результатом. Счётчик совпадений показывает число файлов с подтверждённым совпадением, а не все вхождения шаблонов.

## Стек и его фактическая роль

| Технология | Как применяется |
| --- | --- |
| C++20 | Общий файловый конвейер, поиск байтов, модели результатов и владение ресурсами. RAII закрывает файлы/дескрипторы при выходе и исключениях. |
| Qt 6 Widgets | Главное окно, кнопки, диалоги, таблица. В GUI нет SQL, обхода каталогов и алгоритма обнаружения. |
| Qt Core | QString/Unicode, JSON, время, пути приложения; QCryptographicHash предоставляет потоковый SHA-256. |
| Стандартная библиотека C++ | std::filesystem для обхода; std::thread, mutex, condition_variable для контроллера; atomic_bool для отмены. Фоновый поток не является системной службой. |
| Qt SQL и SQLite | QSQLITE соединяет C++ с локальными .db без отдельного сервера. У каждого потока собственное соединение; транзакции связывают результаты и счётчики. |
| CMake | Находит Qt, формирует цели и вызывает компилятор/линкер. Компилирует MSVC на Windows; Linux предназначен для отдельной сборки. CMake сам не является компилятором. |
| Qt Test и CTest | Qt Test выполняет проверки поведения; CTest запускает четыре набора: audit, core, cli, gui. |
| JSON UTF-8 | Исходные описания сигнатур, машинный вывод CLI и сериализованные поля Job/Result в SQLite. IPC через JSON пока не реализован. |
| Windows/POSIX API | Адаптер file_access открывает файлы read-only и проверяет идентичность/метаданные: HANDLE в Windows, fd/fstat в Linux. |

Python не входит в алгоритм приложения: он использовался как инструмент установки SDK и вспомогательного анализа файлов. GUI, CLI и генератор данных написаны на C++.

## На чём показывать работоспособность

Лучший основной показ — собственный набор с положительными и похожими отрицательными файлами. Он воспроизводим, безопасен и имеет известный ожидаемый результат.

| Файлы | Ожидается |
| --- | --- |
| hash.bin / hash-changed.bin | Совпадение HASH / отсутствие совпадения |
| exact.bin / exact-near.bin | Точный PATTERN / отсутствие совпадения |
| masked.bin / masked-near.bin | Игнорируемый байт отличается — совпадение; значимый отличается — нет |
| fixed.bin / fixed-near.bin | Нужная позиция/размер — совпадение; сдвиг — нет |
| boundary.bin | PATTERN на смещении 65534, пересекает блок 65536 |
| empty; вложенный Unicode-файл | Корректные no_match, включая пустое содержимое и сложный путь |
| large.bin при --large-mib 512 | Блоковое чтение и ручная отмена |

Показ можно повторить из PowerShell в корне проекта. `defense-show` должен отсутствовать:

```powershell
$env:PATH="$PWD/.tools/qt/6.8.3/msvc2022_64/bin;$env:PATH"
./build/audit-fixes/Release/resheto-prepare.exe --source data/demo_signatures.json --output defense-show
./build/audit-fixes/Release/resheto.exe --path defense-show/fixtures --db defense-show/signatures.db --storage defense-show/resheto.db
```

Нажать «Начать»: ожидаются 11 проверенных файлов, 5 совпадений и 0 ошибок. Закрыть окно, открыть с теми же аргументами: последнее задание восстановится.

Проверка независимости от имени файла:

```powershell
Copy-Item defense-show/fixtures/exact.bin defense-show/renamed.txt
./build/audit-fixes/Release/resheto-cli.exe --path defense-show/renamed.txt --db defense-show/signatures.db --storage defense-show/resheto.db --json
```

Ожидается тот же test-exact на смещении 7 и код 1. Для exact-near.bin ожидаются no_match/код 0; для отсутствующего пути — not_checked/код 2; --cancel-after-ms 0 даёт cancelled/код 3. Ошибка имеет приоритет над отменой/обнаружением. Более сложные ошибки чтения и подмена файла проверяются управляемыми автотестами без случайных задержек.

```powershell
./.tools/python/cmake/data/bin/ctest.exe --test-dir build/audit-fixes -C Release --output-on-failure
```

20.10.2026 дополнительно выполнен свежий консольный показ в build/defense-20261020: 11 файлов/5 совпадений; повторное открытие дало идентичный JSONL; копия exact.bin под именем renamed.txt дала test-exact/offset 7; exact-near.bin дала no_match. Вывод сохранён в scan.jsonl, reopened.jsonl, renamed.jsonl, near.jsonl. Пользовательская база demo-run/resheto.db не менялась.

EICAR — отдельная необязательная ручная проверка по docs/eicar_manual.md: для него нужна отдельная подходящая сигнатура. Текущая база из пяти примеров не обязана его обнаруживать. Обычные тесты не создают и не скачивают EICAR; установленную защиту не обходят.

## Формулировка для защиты

«На этапе 3 реализован самостоятельный модуль ручного сигнатурного анализа. Он загружает проверенный снимок локальной базы SQLite, читает файлы блоками, сравнивает SHA-256 и ищет байтовые шаблоны с маской, смещением и ограничениями размера. Работа выполняется в фоновом потоке; ошибки и отмена не превращаются в отсутствие совпадения. Результаты и обнаружения сохраняются транзакционно. GUI, CLI и тесты используют одно ядро. Поставляемые сигнатуры тестовые; полнота распознавания реальных угроз не заявляется. Следующие этапы должны добавить остальные анализаторы и интеграцию службы».

На Windows сборки и тесты проверены. Linux пока не проверен; полная граница глубины 256/257 и обычный symlink в Windows-тестах пропущены из-за ограничений среды. GUI проверен QtTest/offscreen; ручной показ выполняется пользователем. Поиск/фильтрация/сортировка результатов остаются недостатками текущего интерфейса, их нельзя называть реализованными.
