# Показ АС Решето: 5–7 минут

Сначала соберите проект по README. Готовая исправленная сборка на этой машине находится в build/windows/Release. Запуск/подготовка работают в Windows PowerShell 5.1 и PowerShell 7, сеть не нужна. Скрипты сами подключают локальный Qt. Политика выполнения и настройки ОС не меняются.

## Обычный запуск и три поля

```powershell
cd D:\DeleteMeIDareU\Resheto
.\scripts\start.ps1 -Control
```

Этот запуск один раз подготавливает контроль, затем переиспользует его. В GUI уже указаны:

| Поле | Значение от корня проекта |
| --- | --- |
| Объект | build/manual/control/fixtures |
| Сигнатуры | build/manual/control/signatures.db |
| История проверок | build/manual/results.db |

Нажмите «Начать»: ожидается 11 checked, 5 matches, 0 errors. История — отдельный файл результатов, а не ещё одна база правил; GUI создаёт её родительский каталог при запуске задания. Для одного задания нужна одна база сигнатур. Рабочий выбор — distribution/working/current.json, он указывает на SQLite внутри версии. Все signatures.db перечислять не нужно. Старые demo-run/demo-check содержат побайтово одинаковые контрольные базы и не требуются для этого запуска.

## Ход показа

1. **0:00–1:00 — рабочая база.** Подготовьте контроль без открытия окна, затем запустите рабочую конфигурацию:

   ```powershell
   .\scripts\start.ps1 -Control -NoLaunch
   .\scripts\start.ps1
   ```

   Выберите каталог build/manual/control/fixtures. Покажите «Рабочая», HASH 11632/PATTERN 0, источник и версию. После «Начать» — 11 checked/0 matches/0 errors. В distribution/source сохранены MIT-лицензия, ревизия и исходные 11636 строк (4 дубля). Отрицательный ответ на собственных безопасных файлах не доказывает полноту защиты.

2. **1:00–2:30 — тот же модуль с контрольной базой.** В поле «Сигнатуры» выберите build/manual/control/signatures.db. После «Тестовая», HASH 1/PATTERN 4 нажмите «Начать» снова: 11/5/0. Выберите фильтр «Совпадения». hash.bin — SHA-256; exact.bin — точные байты; masked.bin — маска 1011; fixed.bin — offset 17 и размер 32; boundary.bin — offset 65534, пересечение блока 65536. Скопируйте путь/основание. Алгоритм и программа при смене базы не меняются.

3. **2:30–3:30 — обнаружение среди тысяч строк.** Отдельный сценарий нужен только для проверки фильтров:

   ```powershell
   .\scripts\demo-results.ps1 -Output build/show-many-new
   ./build/windows/Release/resheto.exe --path build/show-many-new/many --db build/show-many-new/signatures.db --storage build/show-many-new/results.db
   ```

   Новый каталог содержит 2100 обычных файлов и одну положительную HASH-фикстуру; CLI уже сохранил 2101 checked/1 match/0 errors. По сортировке пути обнаружение идёт после обычных файлов. Фильтр «Совпадения» показывает его сразу. Проверьте поиск «я совпадение», сортировку в обе стороны, копирование полного пути. Это отдельная проверка масштаба интерфейса, для обычной работы она не нужна.

4. **3:30–4:30 — ошибки/отмена/история.** Автоматическая проверка в новом каталоге:

   ```powershell
   .\scripts\demo.ps1 -Output build/show-new
   ```

   Она проверяет обе базы, коды 0/1/2/3 и точное повторное чтение JSONL. Результаты лежат в show-new: working.jsonl, scan.jsonl, error.jsonl, cancelled.jsonl и повторные выводы. Каталоги demo/demo-results должны быть новыми, иначе сценарий откажется их переписывать. Коды: ошибка 2 > отмена 3 > обнаружение 1 > 0. GUI «Остановить» проверяйте на большем безопасном файле, 11 маленьких файлов завершаются слишком быстро.

5. **4:30–5:30 — импорт и встраивание.** По signature_sources.md покажите офлайн-импорт, current.json и отдельные версии. Неуспешная публикация сохраняет старый выбор, начатое задание использует старый снимок. Потребитель из integration.md вызывает библиотеку Resheto::Core без Widgets/Qt Test/CLI.

6. **5:30–6:30 — масштаб и границы.** Покажите performance.md и docs/measurements. Профиль 100000 HASH+1000 PATTERN — синтетика, а не количество реальных угроз. Рабочий источник содержит только HASH. Служба, IPC, эвристика, наблюдение, процессы, сеть и карантин здесь не реализованы; Linux не проверен.

Для другой сборки у скриптов есть -Bin (например build/final-20261025/Release). Старые сборки не содержат новых сообщений GUI, поэтому для повторения исправленного интерфейса используйте build/windows/Release. EICAR — только отдельный добровольный ручной сценарий eicar_manual.md, он не нужен для основного показа; защита ОС не отключается.
