# АС Решето

Решето проверяет файлы по сигнатурам и эвристическим правилам, следит за изменениями в выбранных каталогах и запуском дочерних процессов. Программой можно пользоваться через графическое окно, командную строку или C++-библиотеку. Проверка не требует сети и не запускает проверяемые файлы. Результаты и причины обнаружений сохраняются в SQLite.

## Что реализовано

- **Сигнатурный анализ:** сравнение SHA-256 файла с базой и поиск последовательностей байтов (PATTERN), в том числе с пропусками и заданным положением в файле. Можно проверить отдельный файл или каталог.
- **Статическая эвристика:** проверка исполняемых файлов PE32+ и ELF64 little-endian для x86-64. Два правила ищут область с одновременными правами записи и исполнения и точку входа вне исполняемых областей. Любого из этих признаков достаточно для отметки «подозрительный» в штатном наборе правил.
- **Наблюдение за файлами:** новые и изменённые файлы в выбранном каталоге и его подкаталогах автоматически попадают на проверку. Повторные события объединяются, размер очереди ограничен, наблюдение можно остановить.
- **Анализ процессов:** наблюдение в выбранной области и правило появления у одного родителя не менее трёх дочерних процессов за пять секунд. Отдельно можно включить проверку файлов процессов по сигнатурам и эвристике; результат связан с PID и временем запуска.
- **Интерфейс и история:** фильтры, поиск, сортировка, копирование полного пути и причины обнаружения. Ошибки и неполные проверки показываются отдельно.

## Сборка и тесты

Нужны C++20, CMake 3.21+ и Qt 6.2–6.x: Core, Sql, Widgets, Test и драйвер QSQLITE. Проверены Windows 11 x64, Visual Studio 2022 и Qt 6.8.3 MSVC x64.

Из корня проекта, указав свой Qt SDK:

```powershell
$env:QT_ROOT='C:/Qt/6.8.3/msvc2022_64'
# Для локального SDK проекта: $env:QT_ROOT="$PWD/.tools/qt/6.8.3/msvc2022_64"
if (Test-Path .tools/python/cmake/data/bin) { $env:PATH="$PWD/.tools/python/cmake/data/bin;$env:PATH" }
$env:PATH="$env:QT_ROOT/bin;$env:PATH"
cmake -S . -B build/windows -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="$env:QT_ROOT"
cmake --build build/windows --config Release --parallel 1 -- /nr:false
ctest --test-dir build/windows -C Release --output-on-failure
```

Для Debug замените `Release` на `Debug`. Новые проверки можно запустить отдельно: `ctest --test-dir build/windows -C Release -R '^(lab4|monitor|gui|cli)$' --output-on-failure`. [Фактические результаты и ограничения среды](docs/verification.md).

## Запуск и работа

После сборки выполните из корня проекта:

```powershell
.\scripts\start.ps1          # GUI с рабочей HASH-базой
.\scripts\start.ps1 -Lab4    # Безопасные PE/ELF, эвристика и правила поведения
.\scripts\start.ps1 -Control # Контрольная база HASH/PATTERN и безопасные файлы
```

Скрипты поддерживают Windows PowerShell 5.1 и PowerShell 7. Контрольные данные создаются локально при первом запуске: `build/manual/control` для сигнатур и `build/manual/lab4` для эвристики. История по умолчанию — `build/manual/results.db`.

1. **Ручная проверка:** выберите файл или каталог и нажмите «Проверить». Для эвристики отметьте флажок и укажите JSON-файл с правилами. «Отменить проверку» останавливает только ручное задание.
2. **Наблюдение:** независимо включите «Наблюдать файлы» и «Наблюдать процессы», укажите их каталоги и нажмите «Начать наблюдение». У файлового наблюдения свой флажок подкаталогов. Проверка файлов процессов включается отдельно; список процессов ограничен выбранной областью. «Остановить наблюдение» не отменяет ручное задание.
3. **Результаты:** выберите задание в истории и нужную вкладку: ручная проверка, файловое наблюдение или процессы. Поиск и фильтры находятся внутри вкладок и работают по всем результатам задания до разбиения на страницы. Нажмите на строку, чтобы увидеть основание, правило и фактическую ошибку отдельно. Во вкладке процессов один поиск по PID, пути, основанию или правилу.

Ручная проверка и наблюдение создают разные задания в общей истории. Их можно выполнять одновременно и останавливать независимо. Предыдущие задания доступны в списке истории; просмотр старого результата не останавливает работу и не переключается сам на новое задание.

CLI-пример с безопасными данными:

```powershell
.\scripts\start.ps1 -Lab4 -NoLaunch
$bin='./build/windows/Release'
& "$bin/resheto-cli.exe" --path build/manual/lab4/fixtures/positive.exe --db distribution/working/current.json --heuristics data/heuristic_rules.json --storage build/manual/results.db --json
& "$bin/resheto-cli.exe" --last --storage build/manual/results.db --json
```

`--json` выводит записи JSON, по одной на строку; `--non-recursive` отключает проверку подкаталогов. Коды завершения: **0** — совпадений нет, **1** — есть обнаружение, **2** — ошибка или неполная проверка, **3** — отмена. Каталог для файла истории нужно создать заранее. Отдельная программа `resheto-monitor` запускает наблюдение; по истечении времени `--duration-ms` оно останавливается с кодом 3.

## Как это устроено

Ручная и автоматическая проверки используют одно ядро. Оно читает файл блоками, вычисляет SHA-256 и ищет байтовые шаблоны PATTERN. Полученный хеш сравнивается с базой. Если сигнатуры не совпали и эвристика включена, ядро проверяет структуру исполняемого файла по её правилам. Если база сигнатур недоступна, эвристика продолжает работать, но результат отмечается как неполный с указанием ошибки.

Для поведения программа периодически получает список процессов в выбранной области и отмечает появление дочерних процессов. При включённой проверке файлов процессов тот же файловый анализатор читает их исполняемые файлы — как уже запущенных, так и новых процессов. PID учитывается вместе со временем запуска, чтобы не перепутать разные процессы, которым ОС выдала один номер. Это проверка файла на диске, а не памяти процесса. Ядро сохраняет результаты и их причины, после чего обновляет сведения в окне; сам интерфейс не анализирует файлы и не выполняет SQL.

| Каталог | Содержание |
| --- | --- |
| `src/core/` | Сигнатуры и поиск, PE/ELF и эвристика, файловые/процессные адаптеры, поведение, контроллеры и SQLite |
| `src/gui/`, точки входа в `src/` | Окно, CLI, монитор и средства подготовки |
| `data/` | Контрольные сигнатуры, отдельные JSON-правила эвристики и поведения |
| `distribution/` | Рабочая HASH-база, исходный список хешей, лицензия и сведения об источнике |
| `tests/`, `examples/` | Автотесты, безопасная вспомогательная программа и примеры подключения библиотеки через CMake |
| `scripts/`, `docs/` | Запуск, показ, документация и отчёты |
| `build/`, `.tools/` | Результаты сборки, данные прогонов и локальные инструменты; в Git не включаются |

Промпты, планы, локальные архивы и история проверок также исключены из Git. Старые прогоны и материалы разработки собраны в `.local/archive/`. Пояснения к устройству программы — в [ReadMeToo.md](ReadMeToo.md) и [ReadMeToo_Lab4.md](ReadMeToo_Lab4.md).

Для подключения библиотеки используются CMake-цель `Resheto::Core` и заголовок `<core/api.h>`. Если GUI и тесты отключены, нужны только Qt Core/Sql и Threads; Widgets и Qt Test не требуются. [Пример подключения](docs/integration.md), [детали реализации](docs/implementation.md).

## Базы и правила

Файл `distribution/working/current.json` указывает на текущую рабочую базу SQLite: **11 632 уникальных SHA-256**, версия `malicious-hash-9e6be541abb33859`. Источник — Romain MARCOUX / malicious-hash, лицензия MIT. Копия исходного списка хешей, лицензия и сведения об источнике лежат в `distribution/source`. В рабочей базе **только HASH**; PATTERN для проверки поиска и безопасные примеры поставляются отдельно.

Правила эвристики находятся в `data/heuristic_rules.json`, поведения — в `data/behavior_rules.json`. У них свои версии, независимые от сигнатурной базы. Проверка использует загруженный набор правил до завершения, даже если на диске уже появилась новая версия.

Порог эвристики — 60 баллов; каждое из двух правил даёт 60. Одна структурная аномалия уже вызывает подозрение, две дают 120 баллов и два основания. Баллы задают условие срабатывания, а не процент риска. Несоответствие расширения формату само по себе не используется в штатном наборе.

Чтобы создать новую рабочую базу из сохранённого списка хешей без доступа к сети:

```powershell
& './build/windows/Release/resheto-import.exe' --format sha256-lines --input distribution/source/full-hash-sha256-aa.txt --provenance distribution/source/provenance.json --repository build/new-working --version malicious-hash-9e6be541abb33859
```

Получение метаданных запускается отдельно: `.\scripts\fetch-signatures.ps1 -Output build/new-source`. Обычная сборка, CTest и сканер ничего не скачивают. Проверка новой базы предшествует переключению версии; при сбое прежняя сохраняется. [Источник, обновление и возврат версии](docs/signature_sources.md).

## Показ

Для живого показа через приложение запустите подготовку в новом каталоге:

```powershell
.\scripts\start.ps1 -Lab4 -Directory build/live-new
```

1. В окне включите файловое и процессное наблюдение, а также проверку файлов процессов. Каталоги уже заполнены: `build/live-new/lab4/watched` для файлов и `build/live-new/lab4/processes` для процессов. Нажмите «Начать наблюдение».
2. Скопируйте `negative.exe` из `lab4/fixtures` в `lab4/watched` через Проводник. После результата замените его содержимое копией `positive.exe`, сохранив имя. Во вкладке файлового наблюдения появится эвристическое обнаружение. Оба файла безопасны; запускать их не нужно.
3. Не останавливая наблюдение, выполните ручную проверку `positive.elf`. У двух заданий будут отдельные результаты и состояние. Старое задание можно выбрать в истории; кнопки «Показать проверку» и «Показать наблюдение» возвращают к соответствующим результатам.
4. Запустите собственного безопасного помощника, сначала с одним дочерним процессом, затем с тремя:

```powershell
& './build/live-new/lab4/processes/resheto-safe-helper.exe' --children 1 --hold-ms 6000
& './build/live-new/lab4/processes/resheto-safe-helper.exe' --children 3 --hold-ms 6000
```

Во вкладке «Процессы» видны процессы из выбранного каталога и результаты проверки их файлов. Один дочерний процесс не вызывает поведенческого обнаружения, три вызывают; в подробностях сохраняются PID, ID запуска, правило и события. Результаты остаются после завершения помощника. Остановите наблюдение отдельной кнопкой и снова откройте задания из истории.

Для автоматической сквозной проверки, включая ошибки и повторное чтение истории, используйте другой новый каталог:

```powershell
.\scripts\lab4-demo.ps1 -Output build/show-lab4-new -OpenGui
```

Скрипт оставляет отчёты и базу истории в указанном каталоге; `-OpenGui` открывает уже сохранённые результаты. Для показа текущих событий используйте порядок выше.

Прежние сценарии сохранены: `.\scripts\demo.ps1 -Output build/show-signatures-new` для HASH/PATTERN, ошибок и отмены; `.\scripts\demo-results.ps1 -Output build/show-results-new` для поиска одного обнаружения среди 2 101 результата. [Проверки сигнатурного модуля](docs/verification.md), [его измерения](docs/performance.md).

## Ограничения и Linux

Отсутствие совпадения не доказывает безопасность, а баллы эвристики не означают вероятность заражения. Сам по себе запуск трёх дочерних процессов также не доказывает вредоносность — сейчас это единственный сценарий поведенческого правила.

Список процессов опрашивается периодически: быстро завершившиеся и недоступные процессы могут быть пропущены. Этот анализ не отслеживает обращения процессов к файлам, реестру, сети или памяти других процессов. Наблюдение работает, пока приложение запущено. Ссылки и специальные файлы пропускаются, архивы не распаковываются. Служба, обмен сообщениями между процессами (IPC), сетевой анализ и карантин пока не реализованы.

Linux-адаптеры inotify/procfs написаны, но здесь не собирались и не запускались. Команды для отдельной проверки на Ubuntu 22.04:

```bash
sudo apt install build-essential cmake ninja-build qt6-base-dev qt6-base-dev-tools libqt6sql6-sqlite qt6-qpa-plugins
cmake --preset release
cmake --build --preset release --parallel 4
ctest --preset release
```

Для прежнего безопасного HASH/PATTERN-показа после Linux-сборки:

```bash
./build/release/resheto-prepare --source data/demo_signatures.json --output build/control-linux-new
./build/release/resheto --path build/control-linux-new/fixtures --db build/control-linux-new/signatures.db --storage build/control-linux-new/results.db
```

Контрольная выборка даёт 11 проверенных файлов и 5 совпадений; эти же данные готовит Windows-команда `start.ps1 -Control`. Повторная подготовка требует нового каталога, готовые данные можно запускать снова. Для отдельной Linux-проверки эвристики:

```bash
./build/release/resheto-lab4-prepare --output build/heuristic-linux-new --heuristics data/heuristic_rules.json --behavior data/behavior_rules.json
./build/release/resheto --path build/heuristic-linux-new/fixtures --db distribution/working/current.json --heuristics data/heuristic_rules.json --behavior data/behavior_rules.json --storage build/heuristic-linux-new/results.db
```
