# АС Решето

Решето проверяет файлы, наблюдает за файлами и процессами и анализирует сетевой трафик. У ручной проверки, наблюдения и сетевого анализа свои задания и кнопки остановки. Они могут работать одновременно и сохраняют результаты в одну историю SQLite.

- Сигнатурный анализ вычисляет SHA-256 и ищет байтовые шаблоны PATTERN с масками и смещениями.
- Статическая эвристика проверяет структуру PE32+ и ELF64 little-endian для x86-64. Например, она отмечает область с правами записи и исполнения.
- Наблюдение проверяет новые и изменённые файлы. Для процессов оно отмечает запуск трёх дочерних процессов у одного родителя за пять секунд. Отдельно можно включить проверку файлов этих процессов.
- Сетевой модуль разбирает IPv4/IPv6, TCP и UDP, объединяет пакеты в двунаправленные потоки и применяет правила. Он работает с выбранным интерфейсом или файлом classic PCAP. Живой захват и разбор выполняет отдельный процесс.

## Сборка и тесты

Нужны C++20, CMake 3.21+, Qt 6.2+ в ветке 6.x и драйвер Qt SQLite. GUI использует Widgets, сетевой модуль — Qt Network, тесты — Qt Test.

В Windows выполняйте команды в PowerShell из корня проекта.

```powershell
$env:QT_ROOT='C:/Qt/6.8.3/msvc2022_64'
$env:PATH="$env:QT_ROOT/bin;$env:PATH"
cmake -S . -B build/windows -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="$env:QT_ROOT"
cmake --build build/windows --config Release
ctest --test-dir build/windows -C Release --output-on-failure
```

Для живого захвата на Windows нужен отдельно установленный [Npcap](https://npcap.com/#download) с доступом для текущего пользователя. Проверьте [условия лицензии Npcap](https://npcap.com/license). Решето поставляет только [публичные заголовки SDK](distribution/third_party/pcap/README.md). Проверены Windows 11 x64, MSVC 2022, Qt 6.8.3 и установленный Npcap 1.88.

Для Debian и Ubuntu подойдут следующие команды подготовки и сборки.

```bash
sudo apt install build-essential cmake ninja-build pkg-config qt6-base-dev qt6-base-dev-tools libqt6sql6-sqlite qt6-qpa-plugins libpcap-dev
cmake --preset release
cmake --build --preset release
ctest --preset release
```

Для сетевого модуля на Linux нужна libpcap 1.10+. Право `CAP_NET_RAW` можно выдать сетевому процессу отдельно от GUI. Команды запуска и выдачи прав приведены в [инструкции по подключению](docs/integration.md#linux-и-права-захвата). Этап 5 на Linux ещё предстоит проверить. Обычные сборка и тесты работают офлайн, в том числе без драйвера Npcap и прав захвата. Если сеть не нужна, передайте CMake `-DRESHETO_BUILD_NETWORK=OFF`.

## Работа в приложении

```powershell
.\scripts\start.ps1          # Рабочая HASH-база
.\scripts\start.ps1 -Control # Безопасные файлы и контрольные HASH/PATTERN
.\scripts\start.ps1 -Lab4    # Безопасные PE/ELF и каталоги наблюдения
```

При запуске подставляются рабочая база и JSON-правила эвристики, поведения и сети. Каталоги по умолчанию находятся в `resheto-work/watched` и `resheto-work/processes` рядом с файлом истории. Ручная проверка сначала указывает на каталог файлового наблюдения. Сменить его можно в основном окне, а базы, правила и области наблюдения — по кнопке «Параметры проверки и наблюдения». Явные параметры запуска имеют приоритет. [Безопасный показ файлов и процессов](docs/integration.md#показ-файлов-и-процессов).

Во вкладке «Сеть» выберите источник. Захват на сетевом интерфейсе по умолчанию работает до нажатия «Остановить». Можно задать автоостановку и ограничить захват списком TCP-портов. «Трафик» показывает потоки, «Обнаружения» — срабатывания выбранного задания. Если открыт старый результат, «К запущенному заданию» или «Показать последний результат» переключит на новый. Причины неполной проверки и счётчики доступны в боковой «Диагностике».

Для офлайн-показа подготовьте свои PCAP в новом каталоге и откройте окно с отдельной историей.

```powershell
$bin='./build/windows/Release'
& "$bin/resheto-network-prepare.exe" --output build/network-show-new --rules data/network_rules.json
& "$bin/resheto.exe" --storage build/network-show-new/history.db --network-rules data/network_rules.json
```

Выберите источник «Файл PCAP». В `ordinary.pcap` нет срабатываний. В `control.pcap` три срабатывания после обычных потоков. Откройте «Обнаружения» и выберите строку, чтобы прочитать и скопировать её основание.

Для живого показа выберите источник «Локальный показ». Нажмите «1. Подготовить порты», затем «2. Начать захват». Когда захват готов, выберите «Два обычных соединения» в меню «3. Отправить трафик». Дождитесь автоостановки или завершите захват кнопкой. В отдельных запусках повторите с вариантами «Двадцать разных портов» и «Шесть регулярных попыток». Откройте последнее задание и вкладку «Обнаружения». Третье правило, серия DNS NXDOMAIN, входит в `control.pcap`.

Для примера с обычным HTTP запустите локальный сервер Python в новом пустом каталоге.

```powershell
$httpDir=New-Item -ItemType Directory -Path build/http-example-new -ErrorAction Stop
python -m http.server 8765 --bind 127.0.0.1 --directory $httpDir.FullName
```

В «Сети» выберите «Сетевой интерфейс», укажите `loopback` и TCP-порт `8765`, затем начните захват. В другом терминале выполните `curl.exe --noproxy '*' http://127.0.0.1:8765/`. В истории появится поток на этом порту. Остановите сервер через Ctrl+C после проверки.

Для работы без окна есть `resheto-cli`, `resheto-monitor` и `resheto-network`. Код 0 означает завершение без срабатываний, 1 — обнаружение, 2 — ошибку или неполную проверку, 3 — отмену.

## База и правила

`distribution/working/current.json` указывает на рабочую базу SQLite версии `malicious-hash-9e6be541abb33859`. Она содержит 11 632 уникальных SHA-256 из Romain MARCOUX / malicious-hash (MIT). Контрольные PATTERN поставляются отдельно.

Импорт рабочей базы из сохранённого списка выполняется офлайн.

```powershell
& './build/windows/Release/resheto-import.exe' --format sha256-lines --input distribution/source/full-hash-sha256-aa.txt --provenance distribution/source/provenance.json --repository build/new-working --version malicious-hash-9e6be541abb33859
```

Новый список метаданных можно получить отдельной командой `.\scripts\fetch-signatures.ps1 -Output build/new-source`. Источник, контрольные суммы и замена версии описаны в [signature_sources.md](docs/signature_sources.md).

Правила эвристики, поведения и сети хранятся в трёх отдельных JSON. Сеть ищет обход TCP-портов, регулярные TCP-попытки и серию ответов DNS NXDOMAIN на разные имена. Каждый запуск использует один зафиксированный набор правил. [Условия и пороги](docs/integration.md#сетевые-правила).

## Устройство

| Где | Что там |
| --- | --- |
| `src/core/` | Чтение и анализ файлов, файловое и процессное наблюдение, файловая история |
| `src/network/` | Захват, разбор пакетов, анализ потоков, обмен с отдельным процессом и сетевая история |
| `src/gui/` | Окно, управление заданиями и показ результатов |
| `data/`, `distribution/` | Правила, контрольные сигнатуры, рабочая HASH-база и происхождение компонентов |
| `examples/`, `tests/`, `scripts/`, `docs/` | Примеры подключения, проверки, запуск и пояснения |

C++-приложение подключает `Resheto::Core` через `<core/api.h>` или `Resheto::Network` через `<network/api.h>`. Сетевой процесс передаёт сводки потоков и основания срабатываний контроллеру, который сохраняет их в SQLite. [Подключение модулей и внешние примеры](docs/integration.md).

## Ограничения

Срабатывания показывают признаки, которые нужно проверить. Анализ процессов охватывает доступные процессы из выбранной области и их файлы на диске. Короткие процессы могут завершиться между опросами. Сетевой анализ не собирает IP-фрагменты и TCP-потоки из частей, не расшифровывает трафик и читает classic PCAP 2.4. Ошибки разбора, известные потери и пределы состояния видны в сетевом задании. В программу не входят служба, блокирование трафика и карантин.
